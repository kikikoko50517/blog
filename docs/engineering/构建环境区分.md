# 构建环境区分

构建打包需要手动更改`vue.config.js -> publicPath`，有较大的风险出现因忘记更改而导致上线了测试路径到线上环境上。且后续如果要把构建改为流水线的形式，也不应该进行手动更改打包的操作。



因Vue CLI中的环境变量拥有更高的优先级，因此无法使用--mode的形式来直接更改NODE_ENV（会导致测试和线上的构建产物不一致）。

> 为一个特定模式准备的环境文件 (例如`.env.production`) 将会比一般的环境文件 (例如 `.env`) 拥有更高的优先级。
>
> 此外，Vue CLI 启动时已经存在的环境变量拥有最高优先级，并不会被 `.env` 文件覆写
>



使用`cross-env`库，在`script`中直接新增一个`VUE_APP_BUILD_ENV`来区分不同的环境：`development`、`testing`、`production`

> 请注意，只有 `NODE_ENV`，`BASE_URL` 和以 `VUE_APP_` 开头的变量将通过 `webpack.DefinePlugin` 静态地嵌入到_客户端侧_的代码中。这是为了避免意外公开机器上可能具有相同名称的私钥。
>

打包线上环境：`npm run build`

打包测试环境：`npm run build:test`



使用命令构建打包，避免了**因忘记更改而导致上线了测试路径到线上环境，同时也为后续的CI/CD提供了便利性。**

****

因存在需本地开发请求线上接口的情况，因此需要加`MODE_ENV=local`使`publicPath`的值为正确的值`./`
