# 常量管理

## 常量插件
这个插件提供了一种在 Vue.js 应用中管理和访问常量的方式。它允许你定义包含值和名称的常量，并提供了一些实用方法来获取这些常量的键、值和名称。

### 为什么要使用常量？
在开发中，**“魔法数字”**（Magic Numbers）是指代码中直接使用的具体数字或字符串，这些值没有明确的意义，容易导致代码难以理解和维护。使用常量可以解决这个问题：

+ **提高可读性**：通过使用具有描述性的常量名称，代码变得更容易理解。
+ **便于维护**：当某个值需要修改时，只需更新常量定义，而不必搜索整个代码库。
+ **减少错误**：避免因为误用或错写数字或字符串而引入的潜在错误。

#### 示例
**使用魔法数字的代码**：

```javascript
if (task.status === 1) {
  // 执行任务处理中逻辑
}
```

**使用常量的代码**：

```javascript
if (task.status === this.$constants.TASK_STATUS.IN_PROGRESS) {
  // 执行任务处理中逻辑
}
```

通过使用常量，`1` 被替换为 `TASK_STATUS.IN_PROGRESS`，这更明确地表达了代码的意图。

### 特性
+ **结构化常量**：支持以数组形式定义的常量，第一个元素为值，第二个元素为名称。
+ **实用方法**：自动为每个常量集添加方法，用于获取键、值和名称。
+ **Vue 插件**：将常量全局注入到 Vue 组件中，方便在应用中使用。

### 使用常量
 在 Vue 组件中，可以通过 `this.$constants` 访问常量，也可以直接引入文件来使用。

#### 示例
假设 `TASK_SQUARE` 中定义了如下常量：

```javascript
export default {
  TASK_SQUARE_RECORD_TYPE: {
    SIGN_IN: [1, '每日签到'],
    EXP: [2, '产品体验'],
    NEW: [3, '拉新'],
    PROFILE: [4, '完善手机号'],
    XCH: [5, '兑换商品'],
  },
}
```

你可以在 Vue 组件的模板中直接使用 `.name` 方法来获取常量的名称。假设你有一个任务类型需要显示其对应的名称，你可以这样做：

```vue
<template>
  <div>{{ $constants.TASK_SQUARE_RECORD_TYPE.name(task.type) }}</div>
</template>

<script>
export default {
  data() {
    return {
      // 后端返回的类型
      task: { type: 1, }
    }
  },
  mounted() {
    console.log(
      this.$constants.TASK_SQUARE_RECORD_TYPE.SIGN_IN === this.task.type
    ) // true
    console.log(this.$constants.TASK_SQUARE_RECORD_TYPE.keys()) // 获取所有键
    console.log(this.$constants.TASK_SQUARE_RECORD_TYPE.values()) // 获取所有值
    console.log(this.$constants.TASK_SQUARE_RECORD_TYPE.names()) // 获取所有名称
  }
}
</script>
```



## 全局常量配置
根据 `VUE_APP_BUILD_ENV``环境变量动态加载对应环境的配置文件，并与通用配置合并，生成最终的配置对象。  

+ `**common.js**`：包含所有环境共享的通用配置。
+ `**development.js**`：包含开发环境（development）的特定配置。
+ `**production.js**`：包含生产环境（production）的特定配置。
+ `**testing.js**`：包含测试环境（testing）的特定配置。

配置的加载分别对应启动的脚本：

```javascript
"scripts": {
  "serve": "cross-env VUE_APP_BUILD_ENV=development RUN_MODE=local vue-cli-service serve",
  "dev": "cross-env VUE_APP_BUILD_ENV=development RUN_MODE=local vue-cli-service serve",
  "build": "cross-env VUE_APP_BUILD_ENV=production vue-cli-service build",
  "build:test": "cross-env VUE_APP_BUILD_ENV=testing vue-cli-service build",
},
```

### 为什么要使用常量配置？
+ **环境隔离**：不同的环境（开发、生产、测试等）通常需要不同的配置。例如，开发环境需要请求的`apiRoot`和生产环境是不一样的。可能的话，后续的**活动ID、CDN路径、其余的SDKY**引用路径都要做环境隔离，通过分离这些配置，可以确保每个环境有其专属的设置。
+ **维护性**：将通用配置和环境特定配置分开，有助于维护和管理配置文件。当需要更新通用配置时，只需修改 `common.js` 文件，而无需担心影响特定环境的设置。同时，环境特定配置的修改也不会干扰其他环境的配置。
+ **灵活性**：通过使用环境变量来动态加载和合并配置，可以在构建和部署阶段轻松切换环境。这使得在不同的部署环境中使用相同的代码库，而只需调整环境变量即可适应不同的配置需求。

### 使用常量配置
直接引入文件来使用。

#### 示例
```javascript
import config from '@/config'

const publicKey = config.rsa.publicKey
```
